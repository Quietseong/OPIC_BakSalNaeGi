# OPIc 연습 앱 개발계획 초안

작성: 2026-11-04. 상태: 학습 글 및 공식 규칙 확인 완료 / 영상 구조 확인 완료 / 공식 튜토리얼 세부 미확인 / 구현 진행.

## 목표와 전제

질문 음성을 듣고 영어 답변을 녹음한 뒤, 문항별로 복기할 수 있는 개인용 웹 앱을 만든다. 첫 버전은 PC의 Chromium 브라우저 사용을 가정한다. 목표 등급, 모바일 지원 우선순위, 공개 서비스 여부는 아직 정하지 않았다.

사용자가 제시한 영상과 유사한 연습 경험을 목표로 한다. 공식 시험 규칙과 연습용 영상의 편의 기능은 구분하며, 확인되지 않은 재생 횟수·제한시간·문항 수·난이도 분기 규칙을 실제 시험 규칙으로 구현하지 않는다.

사용자가 권한 창을 처리한 후 조사를 재개했다. 학습 글 본문과 공식 시험소개를 확인했다. 위 표는 최초 조사 이력이며, 최신 확인 결과와 구현 결정은 [자료 분석 및 규칙 명세](research-and-rules.md)를 우선한다. 영상은 길이 34분 43초와 자막 사용 불가 상태까지 확인했으며, 화면 캡처가 최소화된 창 상태로 실패해 문항별 영상 분석은 완료하지 못했다.

## 먼저 할 작업

1. **참고자료 분석**: 관련 학습 글과 영상 확인. 영상 구간별로 시간, 화면, 음성, 사용자 행동, 전환 조건을 기록한다. 질문 원문을 대량 복제하지 않고 진행 방식과 문항 유형 중심으로 정리한다.
2. **시험 규칙 명세**: 공식 출처와 확인 날짜를 붙인 규칙표 작성. 영상 관찰 결과와 다른 부분은 별도 기록한다.
3. **사용자 흐름 정의**: 시작 → 연습 설정 → 마이크 점검 → 질문 재생 → 답변 녹음 → 다음 질문 → 종료 → 복기.
4. **콘텐츠 구성**: 자체 작성 질문과 사용 권한이 있는 음성으로 작은 검증용 세트를 만든다. 주제·유형·난이도·세트 내 순서를 관리한다.
5. **녹음 기술 검증**: 권한 거부, 입력 장치 없음, 오디오 형식, 긴 녹음, 새로고침, 저장 공간 부족을 점검한다.
6. **MVP 구현·검증**: 한 세트를 처음부터 끝까지 수행하고 녹음을 다시 들을 수 있게 한다.
7. **AI 피드백 설계**: 녹음과 복기 흐름이 안정된 후 음성 인식 및 평가 기능을 붙인다.

## MVP 범위

| 기능 | 첫 버전 동작 | 완료 조건 |
| --- | --- | --- |
| 시작·설정 | 검증용 세트 선택, 모드 및 저장 안내 | 설정이 세션에 보존됨 |
| 마이크 점검 | 권한 요청, 짧은 테스트 녹음과 재생 | 녹음 가능 여부를 시작 전에 판단 가능 |
| 질문 진행 | 질문 음성, 문항 번호, 진행 상태, 다음 버튼 | 재생·녹음·전환이 중복 실행되지 않음 |
| 답변 녹음 | 답변별 녹음, 소요시간, 저장 상태 | 다음 문항 전 저장 완료 또는 재시도 제공 |
| 종료·복기 | 질문별 녹음 재생, 다시 연습, 파일 내보내기, 삭제 | 저장한 답변을 다시 열어 들을 수 있음 |
| 오류 복구 | 권한·재생·저장 실패 안내 | 녹음 유실이나 저장 실패를 숨기지 않음 |

첫 구현은 고정 세트의 연습 모드다. 공식 안내에서 확인한 본시험 40분, 12~15문항, 질문 청취 2회, 문항별 답변시간 제한 없음, 중간 난이도 재조정을 실전 모드 설계에 반영한다. 녹음 시작 시점·재청취 가능 시점·이전 문항 이동 가능 여부는 공식 튜토리얼로 추가 검증한다. 실전 모드에서는 힌트와 답변 중 AI 개입을 숨긴다. 연습 모드에서는 질문 텍스트와 재연습을 허용할 수 있다.

로그인, 결제, 소셜 기능, 실시간 대화형 튜터, 대규모 문제 자동 생성, 공식 성적에 준하는 등급 판정은 MVP 이후로 미룬다.

## 제안 기술 구성

- 프런트엔드: React + TypeScript + Vite. 단일 사용자 웹 앱으로 시작한다.
- 녹음: getUserMedia + MediaRecorder. 브라우저 지원 MIME을 실행 시 검사하며 HTTPS 또는 localhost에서 실행한다.
- 저장: IndexedDB에 세션·답변 메타데이터와 음성 Blob 저장. 저장 실패와 브라우저 데이터 삭제에 대비한 내보내기 제공.
- 질문 음성: 처음에는 사전 준비한 음성 파일. 재생 실패 시 다음 행동을 명확히 안내한다.
- 테스트: Vitest로 상태 전이와 저장 동작, Playwright로 핵심 흐름 검증. 실제 장치 녹음은 수동 확인도 수행한다.
- AI 확장: 서버 API를 통해 음성 인식·피드백 제공. 공급자는 추후 결정하며 API 키는 브라우저에 넣지 않는다.

초기에는 서버·계정 없이 로컬 저장으로 완성한다. 다중 장치 동기화나 공개 배포가 필요해지면 인증, 서버 저장, 보관 기간, 비용 상한을 별도로 설계한다.

## 상태 및 데이터 설계

시험 상태: setup → mic-check → ready → playing-question → recording → saving → next-question / completed. 오류는 현재 문항과 저장 상태를 유지한 채 복구 화면으로 연결한다.

- Question: id, topic, type, difficulty, promptText, audioPath, source, usageRights.
- QuestionSet: id, version, orderedQuestionIds, modeRules.
- Session: id, setVersion, settings, startedAt, currentIndex, status.
- Answer: id, sessionId, questionId, recordingBlobKey, mimeType, duration, savedAt, status.
- Feedback(후속): answerId, transcript, evidence, suggestions, modelVersion, createdAt.

질문·세트 버전을 저장해 콘텐츠 변경 후에도 과거 답변과 질문의 연결을 유지한다. 다음 버튼 연속 클릭과 저장 중 이동은 상태 전이 규칙으로 제어한다. 남은 시간은 타이머 호출 횟수가 아닌 기준 시각으로 계산한다.

## 개발 단계와 검수 기준

| 단계 | 산출물 | 통과 기준 | 예상 작업일 |
| --- | --- | --- | --- |
| 0. 조사·명세 | 자료 목록, 영상 타임라인, 공식 규칙표, 화면 흐름 | 확정 규칙과 가정이 구분됨 | 1–2 |
| 1. 기술 검증 | 한 질문 재생·녹음·저장·재생 프로토타입 | 새로고침 후 저장 음성 재생 가능 | 1 |
| 2. MVP | 설정·세트 진행·종료·복기 | 세트 전체를 완료하고 답변별 재생·삭제·내보내기 가능 | 3–4 |
| 3. 안정화 | 오류 복구, 상태 전이 테스트, 사용 안내 | 권한 거부·연속 클릭·새로고침·저장 실패 검증 | 1–2 |
| 4. AI 피드백 | 전사·근거 기반 피드백·재시도 | 실패해도 원본 녹음 보존, 피드백 비용 측정 | 별도 2–4 |

예상치는 1인 개발의 초안이며 자료 정리와 콘텐츠 제작량에 따라 조정한다. MVP 목표는 6–9 작업일이며 AI 확장은 별도다.

## 테스트 및 평가

- 자동: 상태 전이, 녹음 저장 실패, 세트 순서, 중복 전환 방지, 세션 재개, 데이터 삭제.
- 브라우저 통합: 가상 마이크로 시작부터 종료·복기까지 진행.
- 실제 장치: 권한 거부, 무음 입력, 장치 분리, 화면 이동, 오디오 출력이 녹음에 섞이는 상황, 장시간 세션.
- 사용자 검수: 질문을 놓치지 않는지, 저장 상태가 명확한지, 복기에 필요한 클릭이 과하지 않은지 확인.
- AI 단계: 과제 수행, 답변 구성, 문법·어휘, 유창성을 근거와 함께 제시한다. 전사만으로 발음을 판정하지 않고 실제 오디오 평가 가능 여부를 별도로 검증한다. 등급 추정은 공식 성적과 구분하고 검증용 답변으로 일관성을 평가한다.

## 운영·콘텐츠 결정

영상과 게시글은 참고 링크로 기록한다. 앱 배포용 질문·음성은 자체 제작 또는 이용 허락을 받은 자료로 구성한다. AI 전송 기능에는 전송 대상·목적과 삭제 방법을 표시하며, 첫 버전의 로컬 녹음을 자동으로 외부에 전송하지 않는다.

## 구현 확정 사항 (2026-11-04)

사용자가 구현을 승인해 아래 결정으로 진행한다. 근거는 [자료 분석 및 규칙 명세](research-and-rules.md)의 2026-11-04 검증 결과와 `docs/decisions.tsv`에 있다.

- 기술: React 19 + TypeScript + Vite 6(Node 20.18 호환), Vitest + fake-indexeddb, Playwright(가짜 마이크 장치).
- 질문 음성: `npm run audio`가 Windows 영어 음성으로 문항별 WAV를 만든다(git 제외). 앱은 WAV, 브라우저 음성 합성(speechSynthesis), 질문 텍스트 순서로 시도한다. ego Chromium에는 음성 합성 목소리가 없어서 WAV를 기본으로 정했다. 모두 실패하면 질문 텍스트를 보여 주고 답변을 계속할 수 있다.
- 콘텐츠: 영상과 같은 구조(자기소개, 3문항 묶음, 롤플레이 묶음, 비교·이슈)의 자체 작성 세트 1개. 2차 세션은 쉬운·비슷한·어려운 세 경로를 둔다.
- 모드: 연습 모드는 질문 텍스트를 보여 주고 다시 듣기 횟수에 제한이 없으며, 90초·120초 목표 시간을 선택할 수 있다(자동 종료 없음). 실전 모드는 질문 텍스트를 숨기고 청취 2회, 전체 40분, 7번 문항 뒤 난이도 재선택을 적용한다.
- 저장: 답변은 시도 단위로 저장하며 재답변이 원본을 덮어쓰지 않는다. 메타데이터와 음성은 한 트랜잭션으로 저장한다. 녹음 길이는 앱이 직접 측정한다.
- 미확인 규칙에 대한 앱 자체 규칙: 다시 듣기는 질문 재생이 끝난 뒤 녹음 전에만 가능하다. 실전 모드에서는 이전 문항으로 돌아갈 수 없다. 40분이 지나면 녹음 중인 답변을 저장하고 종료한다.
